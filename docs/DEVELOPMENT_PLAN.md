## 产品目标与安全不变量

将指定 ChatGPT 对话的可见内容、分支关系和可取得的附件真实字节保存到本地档案；支持 ZIP 导出/恢复、完整性核验，并将历史与用户选定的原始附件安全带入普通新聊天。

1. 不修改或删除源对话/项目；不自动点击 Send，不静默重试。
2. 不覆盖目标聊天已有草稿或附件；目标必须是空白普通新聊天，不是 Project、Temporary 或旧对话。
3. 只有非零真实字节通过大小与 SHA-256 校验才可标记已保存；未知、缺失、损坏分别呈现。
4. 采集、实时缓存、接续均绑定明确来源对话、标签页、任务和目标文档；页面身份变化即停止。
5. 认证信息、Cookie、签名 URL、真实对话正文和附件不得进入 GitHub、ZIP 元数据或诊断日志。
6. 上传状态只有在网页给出可验证完成状态时才标记确认；未知时交还控制权，不自动重试、不发送。
7. ZIP 恢复必须验证 schema、路径、条目、大小、哈希和完整性；拒绝截断、歧义或越界输入。
8. 任何自动化测试均不得替代真实账号、真实旧资料或真人验收。

## 剩余验收清单

真实账号步骤见 `docs/REAL_ACCOUNT_ACCEPTANCE.md`。使用独立 Edge 配置和无敏感内容的测试对话，所有证据仅记录用例 ID、浏览器版本、候选 SHA、状态、错误码及必要脱敏截图；不上传真实 JSON、附件、Cookie、Token 或签名 URL。

必须完成：
- 当前 ChatGPT 登录页面：来源绑定、可见消息与分支映射、文件选择器、附件上传状态。
- 包含 PDF、XLSX、CSV、图片、助手生成文件的测试对话：原文件名、字节数、SHA-256、缺失原因逐项核验。
- 浏览器关闭/重启后档案与 Blob 持久性；ZIP 导出、独立恢复、恢复不覆盖原档案。
- 官方导出 ZIP 与本地档案逐文件对照；旧对话及已失效远端文件分别记录可读、不可读和未知。
- 12、21+ 附件批次、长历史、大文件、磁盘空间不足、中断恢复及边界拒绝；未测容量不宣称上限。
- 新普通聊天接续：目标身份正确、原始附件内容可读、早/中/末历史事实可核验；既有草稿/文件、Project、Temporary、旧对话和未知上传均安全拒绝。
- 至少一名未参与开发的用户独立完成保存、查找、接续任务；记录任务成功、错误、放弃、恢复和耗时。读屏/键盘验收单独记录。

## 交付与放行规则

1. 每个代码变更在功能分支完成，提交聚焦 PR；准确 HEAD 的 Ubuntu 与 Windows CI 均通过。
2. 对应测试必须覆盖安全不变量和失败路径；不得删断言、吞错、扩大 success 定义或把 unknown 改成 success。
3. 构建产物必须来自准确提交 SHA，并核对 BUILD_INFO、SHA256SUMS 和 artifact digest。
4. 所有真实账号步骤由所有者/授权测试者执行；云端 Agent 不请求账号凭据，不访问用户本地设备，不代签人工验收。
5. 真实账号、旧资料、真人 UX 任一必需门禁未完成，状态保持 pending/blocked；不能发布稳定版，不能合并 main。
6. 完成所有验收后仍需所有者明确批准合并和发布；本计划不构成该授权。
